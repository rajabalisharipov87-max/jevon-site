# JEVON — общий проект вид

Заказы, сотрудники, посещаемость и фотографии работают в одном приложении `jevon-order-status` и общей базе PostgreSQL `jevon`.

## Запуск

1. Запустите службу PostgreSQL. Подключение задаётся переменной `DATABASE_URL` в `jevon-order-status/.env`.
2. Запустите `start.bat`. Скрипт устанавливает отсутствующие зависимости, готовит схему, собирает приложение и запускает его на порту 8080. Сборка выполняется при каждом запуске, поэтому старт занимает около минуты. Для разработки с горячей перезагрузкой запускайте `start.bat dev`.
3. Откройте:
   - http://127.0.0.1:8080 — заказы и кабинеты.
   - http://127.0.0.1:8080/attendance — приход и уход с фотографией.
   - http://127.0.0.1:8080/employees — сотрудники и журнал посещаемости; вход кодом менеджера или начальника цеха.

Держите окно запуска открытым; Ctrl+C останавливает приложение. Второй сервер на 8081 больше не нужен.

## Доступ из сети и HTTPS

Без HTTPS браузер не даёт доступ к камере, а вход руководителя не сохраняется. Поэтому наружу на порту 8080 работает Caddy с HTTPS, а само приложение переносится на внутренний порт 3000, доступный только с этого компьютера. Порты 80 и 443 не используются.

1. Скачайте `caddy.exe` с https://caddyserver.com/download (Windows amd64) и положите рядом с `Caddyfile` в корне проекта.
2. В `jevon-order-status/.env` добавьте строку `APP_PORT=3000`.
3. Откройте в брандмауэре Windows и пробросьте на роутере порт 8080 на этот компьютер.
4. Запустите `start.bat`, затем в отдельном окне из корня проекта: `caddy run`.
5. Откройте `https://94.199.16.44:8080/attendance`. Адрес `http://…:8080` автоматически перенаправляется на `https://`. Caddy выдаёт собственный сертификат, поэтому браузер один раз покажет предупреждение — его нужно принять на каждом устройстве.

Caddy передаёт приложению реальный адрес клиента, поэтому ограничение попыток ввода кода считается для каждого устройства отдельно.

## Хранилище

`migration/sql/0001_initial_schema.sql` содержит схему заказов, материалов, чертежей, статусов, проектов, сотрудников, событий посещаемости, настроек и файлов. Фотографии сохраняются в `stored_files.data` (BYTEA); событие посещаемости связано с сотрудником и фотографией внешними ключами. Фото и событие сохраняются одной транзакцией. Коды посещаемости хранятся в виде HMAC, их значения не возвращаются API.

При первом запуске `migration/setup-postgres.mjs` переносит существующую локальную SQLite, локальные фотографии и исходный каталог заказов в PostgreSQL. Операция выполняется транзакционно и помечается в `app_settings`, поэтому при следующих запусках данные не импортируются повторно. Исходная SQLite сохраняется. Исторические записи и сотрудники Google Apps Script не импортированы: их исходный экспорт отсутствует. Созданы начальные записи существующих ролей; добавляйте работников через страницу сотрудников.

Подпись сессий хранится в `app_settings`. Можно задать собственный `BRIDGE_SECRET` в `.env`; после смены этого ключа потребуется обновление кодов посещаемости, так как их HMAC зависит от ключа. Настройки внешних интеграций берутся из переменных окружения. `.env` исключён из Git.

## Команды

Из папки `jevon-order-status`:

```powershell
npx.cmd --yes pnpm@11.25.0 install --frozen-lockfile
npx.cmd --yes pnpm@11.25.0 db:check
npx.cmd --yes pnpm@11.25.0 db:setup
npx.cmd --yes pnpm@11.25.0 dev
npx.cmd --yes pnpm@11.25.0 build
npx.cmd --yes pnpm@11.25.0 start
```

`db:check` проверяет подключение и счётчики записей без изменения данных. SQL-миграции старого Cloudflare/D1 сохранены в `migration/legacy/sqlite/`; для общего проекта используется PostgreSQL-схема. Команды прежнего Cloudflare-профиля сохранены как `dev:cloudflare`, `build:cloudflare`, `start:cloudflare`.

Папка `jevon-hastu-nest` сохранена как исходная версия; её интерфейс перенесён в `jevon-order-status/app/attendance`. Папка `jevon-order-tracking` остаётся отдельным клиентским приложением и в объединение кабинета сотрудников с посещаемостью не входит.

## Портал отчётов и пользователи

http://127.0.0.1:8080/reports — защищённый портал с обзором заказов, пользователей и посещаемости. http://127.0.0.1:8080/reports/users — создание персональных учётных записей и список пользователей (только администратор). Учётные записи портала отдельны от PIN-кодов сотрудников; их можно связать с записью сотрудника. Две роли: администратор (отчёты и управление пользователями) и аналитик (отчёты).

Первоначальный администратор: логин `admin`, автоматически созданный пароль находится в `jevon-order-status/.sites-runtime/reports-admin.json`. Вместо генерации можно задать `REPORTS_ADMIN_LOGIN` и `REPORTS_ADMIN_PASSWORD` до первого запуска. Подробности аутентификации и первоначальной настройки — в `migration/README.md`. Новый SQL-файл: `migration/sql/0002_reports_auth.sql`.

Все новые изменения PostgreSQL оформляются отдельными SQL-файлами в migration/sql. Создание базы и таблиц для хостинга: pnpm db:deploy. Подробная инструкция — migration/README.md.
