# Проверка кода — 3 октября 2026

Проверены инструкции запуска, конфигурация, обработчики авторизации и статический анализ двух приложений заказов. Это выборочная проверка, а не полный аудит.

## Найденные проблемы

1. **Высокий приоритет: регистрация клиента не подтверждает владение телефоном.** В `jevon-order-tracking/app/api/client-auth/route.ts` ветка `register` проверяет наличие заказа с указанным телефоном, создаёт учётную запись и возвращает код и cookie. Проверки SMS или одноразового приглашения нет; параметр `token` в этой ветке не проверяется. Зная номер клиента, можно зарегистрироваться первым и получить доступ к его заказам. Нужна проверка владения номером либо приглашение менеджера до создания аккаунта.
2. **PIN сотрудников зафиксированы в исходниках.** `jevon-order-status/app/role-session.ts` содержит четырёхзначные коды всех ролей. Подпись cookie и ограничение попыток не заменяют индивидуальные учётные записи и секретные коды вне репозитория.
3. **ESLint не проходит.** Кабинет сотрудников: 7 ошибок и 17 предупреждений (`any` в статистике и данных панели, синхронное обновление состояния в эффекте кабинета начальника). Клиентское приложение: 3 ошибки и 1 предупреждение (обновление состояния в эффектах, элемент `img`).
4. **Локальные данные требуют настройки.** Для заказов нужны миграции D1 и локальный `BRIDGE_SECRET`; чистая установка не содержит рабочих заказов и аккаунтов. Учёт посещаемости отправляет данные во внешний Google Apps Script — локальный сервер не делает эту интеграцию локальной.

## Проверки и изменения

- `tsc --noEmit` успешно завершился в `jevon-order-status` и `jevon-order-tracking`.
- В `start.bat` добавлен поиск Node.js в стандартной папке Windows, если PATH терминала устарел, и адрес запуска `127.0.0.1`.
- Кабинет сотрудников запущен в фоне на `http://127.0.0.1:5173`: главная страница вернула HTTP 200, `/api/auth` без сессии — 401. Клиентский кабинет на `http://127.0.0.1:5174` первоначально вернул HTTP 200 и корректный ответ `/api/client-auth`, но последующая проверка `/orders` дала 500. Повторные запуски на Node.js 22.16.0 и 26.10.0 завершились ошибками Vinext/Workerd (`ECONNRESET` / internal error); стабильный запуск клиентского кабинета не подтверждён, сервер остановился. Полные бизнес-сценарии не проверялись: рабочие данные и секреты не настроены.
- Встроенный браузер недоступен в этой сессии; визуальная проверка интерфейса не выполнена.
- В приложении посещаемости исправлены 6 ошибок TypeScript: тип ответа JSON на клиенте и проверка входного JSON на сервере. Повторная проверка типов прошла; ESLint — без ошибок, с одним предупреждением о `img`.
- Для посещаемости добавлена команда `dev:local` (Next.js, `127.0.0.1:5175`), потому что Vinext/Workerd на этом компьютере повторно завершался с `ECONNRESET`. Next.js успешно вернул HTTP 200; запрос с пустым JSON — 400. `start.bat` использует эту команду для варианта 3. Отправка данных в Google Apps Script не тестировалась, чтобы не создавать реальные записи посещаемости.
- Производственные базы, опубликованные сайты и внешние данные не изменялись.
